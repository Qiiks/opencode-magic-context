# Rust MC mode: ownership units U9-U11 (v5 — REVISE-with-pins folded, build-ready)

Extends .alfonso/plans/rust-mc-mode-v1.md (U1-U8 shipped and drive-proven 2026-07-17/18).
Scope: move dreamer execution, memory authority, and notes to the module for rust-mode
projects. Everything behind transform_mode:"rust"; default ts; no behavior change for
anyone else. v2 resolves the round-1 review's 6 BLOCKERs + 5 HIGHs; every resolution is
in-plan, none deferred.

## U-AUTH (new, builds first) — durable project authority state machine

One mechanism every other unit consumes. Per (project, domain) authority row in the
MODULE store (module is the arbiter because it is the single daemon all processes reach;
a context.db row cannot fence a process that never opens the module):

  state: TS | PREPARING | MODULE | DRAINING
  generation: u64, bumped on every transition
  domain: memories | notes  (compartments stay coverage-governed by the transform spine)

Rules:
- Every authority-mutating op (facade memory/note ops AND the TS write paths via a
  cheap cached module query, TTL <= 1 pass) carries the generation it observed; the
  authority side rejects on mismatch (typed retryable). Unreachable module = TS paths
  keep working only while state is TS; in MODULE state, module-unreachable means the
  mutation FAILS LOUD (consistent with rust-mode failure semantics: no silent fallback).
- PREPARING (flip TS->MODULE): (1) transition to PREPARING bumps generation — TS writers
  observing PREPARING reject with retry-after, closing the check-then-flip race; (2) seed
  runs to a captured context.db upper bound; (3) CONTENT verification: per-row hash
  compare over (content, status, category, classification columns) for the full pool, not
  count/max-id — mismatch aborts back to TS with a loud report; (4) transition to MODULE.
- DRAINING (flip MODULE->TS) is U8-extended, exact order:
  (1) enter DRAINING (generation bump; module mutations now reject, transforms still
  serve from module), (2) capture per-domain changefeed upper bounds, (3) drain memories
  + notes changefeeds through those bounds into context.db, (4) mirror compartments
  through final coverage, (5) run existing U8 marker/tag reconciliation, (6) verify
  per-domain row-hash checksums, (7) transition to TS (generation bump).
  Crash mid-DRAINING: state persists; next boot resumes the drain (steps are idempotent
  by cursor). Transforms during DRAINING stay module-served.
- Multi-process safety falls out: a stale process that never re-read state still sends
  its observed generation and gets rejected after any transition.

## U-FEED (new, builds with U-AUTH) — one changefeed/mirror protocol

Round 1 was right that three ad hoc mirrors will drift. One shared transport:
- Module keeps an append-only per-domain changefeed: (feed_seq, domain, op:
  insert|update|tombstone, module_row_id, full_row_snapshot, content_hash). Memory
  inserts APPEND TO THE FEED (fixes the missed-inserts blocker: the mutation log stays
  what it is; the feed is a superset written in the same fenced transaction as the row).
- TS mirror service: mirror.pull(domain, cursor, limit) -> page; apply page in ONE
  context.db transaction; advance durable cursor only after commit. Idempotent by
  (domain, feed_seq). Domain-specific row application stays separate (memories update
  vectors, notes resolve anchors); paging/cursor/retry/diagnostics shared.
- IDENTITY: mirror rows do NOT reuse context.db integer ids. A mapping table
  mirror_identity(domain, module_project, module_row_id) -> context_row_id; the mirror
  allocates fresh context.db ids on first sight and reuses via the map. Kills the
  cross-project id-collision blocker without global id coordination. ctx_memory ids
  shown to the agent in rust mode are MODULE ids (the facade already returns them);
  the m0/m1 render uses module ids consistently (single id vocabulary on the wire).
- EMBEDDINGS: when the mirror applies an update with a changed content_hash, the same
  transaction deletes the stale vector row. The embedding sweep then regenerates from
  the mirrored row; saveEmbeddingIfHashMatches (extended to ALL save paths, including
  ensureMemoryEmbeddings' currently-unguarded call) rechecks the mirrored hash at save.
  Authority lag beyond the newest pull is bounded and converges: a later pull with a
  newer hash deletes the vector again. Vectors are cache-invisible, so lag is a
  search-quality bound, not a correctness hazard.

## U9 — dreamer execution via broca (split by real execution shape)

- SCHEDULING, leases, prompts, parsers, appliers stay TS (unchanged from v1).
- U9a zero-tool producer jobs: classify-memories (the only genuinely zero-tool task).
  New module op `dreamer.run_task` — TASK-ENUMERATED, not generic: request carries
  {task: "classify", payload (bounded, host-rendered prompt body), authority_generation}.
  The MODULE owns per-task system-prompt class, model chain, temperature, max tokens,
  output cap, timeout, and session namespace (mirrors historian producer calibration
  constants). No caller-supplied prompt template, no arbitrary model selection: closes
  the producer.run trust hole.
- U9b read-only agentic manifest jobs: map-memories, verify, verify-broad. These need
  the repo-reading tool loop, so they gate on Broca tool-provider integration: MC serves
  the locked read-only tool universe as a subc tool provider (Broca contract pins,
  pm_c107f385); the permission map of DREAMER_MEMORY_MAPPER_AGENT translates to the
  served allowlist. Builds AFTER U9a proves the run_task plumbing.
- U9c mutating agentic jobs: curate, retrospective, refresh-primers, maintain-docs.
  Last; adds ctx_search/ctx_memory facade tools to the served universe with the same
  ownership guards the CC leg enforces. maintain-docs keeps host-side protected-region
  hash assertion on apply.
- APPLIES: all dreamer DB writes (verify/classify/curate/map results) go through
  REVISION-AWARE authority ops: each manifest row carries the content_hash the prompt
  input showed; the module op rejects rows whose current hash differs (stale-view CAS),
  host retries the task or drops the row. New facade ops added for the writes the CC
  leg never needed: set_classification, set_verification, set_mapping — each fenced,
  each hash-guarded, each feed-appending.
- PRIVACY/RETENTION: broca dreamer sessions are purged on terminal (success or failure)
  via the runner's session-delete op; crash orphans swept by namespace prefix with age
  gate; keep_subagents does NOT apply to dreamer tasks (they carry memory-pool
  snapshots); retrospective purges unconditionally (raw user text). Pinned in the unit's
  tests.
- RECURSION EXEMPTION: no prefix trust. The module mints the child session id at
  run_task dispatch and registers it in an in-memory active-run set; the transform
  handler exempts ONLY registered ids (checked after route binding validation).
  mc-historian keeps its existing mechanism until it migrates to the same registry
  (folded into U9a).

## U10 — memory authority flip (consumes U-AUTH + U-FEED)

- Route flip: when authority state is MODULE, rust-tool-backends routes ALL ctx_memory
  actions to the facade ops; TS storage-memory write paths check the cached authority
  state and reject with the transition error when not TS-owned. Dreamer appliers use
  the U9 revision-aware ops when the project domain is MODULE.
- Mirror-back via U-FEED (dashboard, unified ctx_search FTS, embeddings), identity via
  mirror_identity map.
- CACHE-VISIBILITY DOCTRINE (each classification field, explicit):
  - content/status/category: render into m0/m1 -> mutation-log + m1 delta semantics,
    exactly the CC-leg behavior (already shipped, drive-verified).
  - importance: affects SELECTION ORDER at the next compose, not current bytes (same as
    TS: #7034). Changes ride the next natural bust. No new mechanism.
  - scope/shareable REVOCATION: security-sensitive. A revocation appends a feed row AND
    bumps the module-side workspace fingerprint input, which the existing
    cached_m0_workspace_fingerprint HARD trigger already consumes -> exactly one
    coordinated fold removes the foreign memory; defer passes before it replay frozen
    bytes (defer-byte-safe by the existing invariant that defers never re-render).
    Grant (non-revocation) changes ride the next natural bust like importance.
- Flip procedure per project: PREPARING seed+verify (U-AUTH), then route flip, then a
  drive beat asserting a ctx_memory write lands module-side, feeds back to the mirror,
  and appears in the next m1 delta.

## U11 — notes (rewritten as a schema + CAS unit)

Honest size: the module mc_notes table is a minimal CC-leg surface; the TS smart-note
machinery needs full state. This unit:
- SCHEMA: module migration extends mc_notes to the complete note model: status
  (active|pending|ready|dismissed), surface_condition, compiled_check + source_revision
  + compiled hashes, schedule/next_check_at, failure counters, quarantine fields,
  policy_version, anchor (see below), dismissal resolution. Feed-appending like memories.
- CAS OPS for the evaluator: note.claim_due (leases a due pending note to an evaluator
  instance), note.transition(id, from_status, source_revision, to_status, result) —
  rejects on any mismatch, so evaluate/edit/dismiss races resolve by CAS, not ordering
  luck. Evaluation itself (QuickJS, network, SSRF) stays TS and talks only through
  these ops.
- DELIVERY FENCE: surfacing is module-side (it owns ordinals). A note selected for
  surfacing is transitioned ready->surfaced-in-flight in the same fenced transaction
  that emits it into the transform output; a concurrent dismissal CAS-fails and the
  dismissal wins on retry ordering (dismiss beats surface: user intent).
- ANCHORS: canonical anchor = module block id + the ABSOLUTE ORDINAL resolved at write
  time (both stored). Mirror rows carry the ordinal so TS dashboard/search render
  @msg N unchanged. Seed converts existing anchorOrdinal-only rows by ordinal (block id
  null-allowed for legacy rows; surfacing falls back to ordinal).
- SEED: same PREPARING protocol as memories (hash-verified completeness before flip).

## Sequencing (v3: apply path before its consumers)

## v3 amendments (round-2 findings, each resolved in-plan)

B1 SAME-DATABASE FENCE, then permits. The TTL cache is dead. The fence that closes the
straddle race lives in context.db itself: a per-project `authority_managed` marker row
written and committed BEFORE the module row enters PREPARING. Every TS memory/note
write path checks the marker INSIDE its own write transaction (same SQLite database,
serialized by the write lock, so no partition or TTL can straddle it): marker absent =
legacy TS behavior, zero new failure modes for never-opted-in projects; marker present
= the write requires a module-issued one-shot write permit (bounded lifetime, generation-
stamped) or fails loud. PREPARING issuance: stop granting permits, wait out the permit
lifetime, then capture the seed bound. Module-unreachable under a present marker = write
fails loud (rust-mode failure semantics); module-unreachable with no marker = normal TS.
Flip-back's final step deletes the marker in the same transaction that re-activates TS
writers.

B2 WRITER INVENTORY + STRUCTURAL ENFORCEMENT. (a) Module store: feed appends move into
SQLite triggers on mc_memories/mc_notes (insert/update/delete), so every writer,
including promote_facts_tx and any future direct SQL, appends by construction; the
build inventories all mutation sites and adds a trigger-coverage test (mutate via every
site, assert feed rows). (b) Dashboard: it reads context.db directly, so it sees the
authority_managed marker; under a present marker the memory edit surface goes read-only
with a "managed by the Rust module" notice (structural: the Rust backend checks the
marker before every mutation and rejects). Dashboard writes-via-module is a later unit;
read-only-under-management closes the unfenced-second-authority hole now.

B3 CRASH-IDEMPOTENT SEED IDENTITY. Module memories/notes gain a durable source key
(context_store_uuid, context_row_id) with a unique index; the seed upserts by source key
(re-running after a crash converges, never duplicates). mirror_identity is populated at
seed time with the ORIGINAL context ids, so pre-existing rows keep their dashboard ids
forever; only module-born rows allocate fresh context ids at first mirror application.
Reference columns (superseded_by_memory_id, merge provenance) translate through the map
in both directions; the build enumerates every reference column and tests round-trip
translation including flip-back.

B4 REAL VISIBILITY EPOCH. The workspace fingerprint today covers membership + category
policy only, and visibility predicates ignore scope/shareable; both facts verified in
round 2. U10 adds: (a) module-side per-project memory_visibility_epoch, bumped in the
same transaction as any write that changes scope/shareable/status of a row visible to
workspace members; (b) the epoch of EVERY member folds into workspace_fingerprint (the
existing HARD trigger consumes it unchanged); (c) foreign-memory SQL predicates (render,
search, delta, watermark) gain the scope/shareable filter so the epoch and the bytes
agree. Revocation therefore = one epoch bump = exactly one coordinated fold; defers
before it replay frozen bytes.

B5 U11 DELIVERY LEDGER, honest semantics. States gain `surfacing` (claimed for output)
and `surfaced` (delivery acknowledged). Linearization rule, stated plainly: dismissal
before claim suppresses delivery (CAS on transition wins); dismissal after claim cannot
retract bytes already serialized — it suppresses all FUTURE replay and resurfacing.
Delivery ledger row (note id, delivery id, transform pass id, acked_at) written in the
claim transaction; a lost response (pass rejected/LKG-served) leaves the ledger un-acked
and the note returns to ready for retry. Sticky/persisted anchor cleanup on dismissal is
part of the unit: the TS note-nudge anchor store is swept for dismissed note ids in the
same mirror application that carries the tombstone, so dismissed output cannot resurrect
through anchor replay.

B6 RESEQUENCED (see Sequencing): U10 lands the revision-aware classification/
verification/mapping ops before U9a runs, so classify applies never touch the
unconditional TS setMemoryClassification path under a managed project. For unmanaged
(pure-TS) projects U9a is out of scope by definition (dreamer-via-broca is a rust-mode
feature).

H1 DRAINING JOURNAL. The DRAINING row persists: captured per-domain upper bounds, drain
generation, per-domain cursors, per-step completion bits (the 7 steps), coordinator
lease (single drainer, lease-expiry recovery), and checksum results. Verification
failure = stay DRAINING, alarm loud, manual retry op; extra stale context rows found
during checksum are reported, never silently deleted.

H2 EXACT SCHEMA CONTRACT. The build spec enumerates every module column as a 1:1 of the
TS note model: type, status, content, surface_condition, ready_at, ready_reason,
manifest_json, compiled_check, compiled_at, source_revision, check_status,
check_version, policy_version, logic_failure_count, network_failure_count,
check_false_since_at, check_last_liveness_at, next_check_at, schedule, quarantined_at,
quarantine_reason, dismissed_at, dismissal_resolution, anchor_block_id, anchor_ordinal,
session_id, project scope columns, created/updated timestamps — each with nullability
and default matching the TS schema, plus the feed snapshot carrying the full row.

H3 ORPHAN OWNERSHIP MARKER. run_task persists (run id, child session id, minted_at) in
the module store at dispatch; the orphan sweep deletes only sessions whose id matches a
persisted ownership row past the age gate. Prefix matching is diagnostics-only.

## v4 amendments (round-3 findings, each an explicit protocol decision)

R3-B1 SEED BOUND UNDER A WRITE BARRIER, not permit expiry. PREPARING order: (1) stop
permit issuance; (2) acquire a context.db WRITE BARRIER: `BEGIN IMMEDIATE` on context.db
itself — under SQLite's single-writer lock this cannot start until every in-flight write
transaction (permitted stragglers included) has committed or rolled back; (3) capture the
seed upper bound INSIDE that barrier transaction; (4) release. Permit lifetime becomes an
operational bound on how long PREPARING can stall at step 2, not a correctness input.
WAL-mode nuance pinned for the build: readers are irrelevant; the barrier serializes
against writers exactly because context.db allows one writer at a time.

R3-B2 AUTHORITY KEYED BY STORE IDENTITY. U-AUTH rows key on (context_store_uuid,
project, domain). context_store_uuid: minted once into a context.db meta row on first
open by a plugin version carrying this feature; Engram restore restores the row (same
uuid, deliberately — a restored store IS the same store, and restoring a pre-marker
snapshot yields marker-absent + uuid-match, which the module detects as REGRESSED state:
authority row exists for that uuid but the marker is gone → module refuses permits and
raises a loud repair op that re-runs PREPARING verification rather than silently
reopening TS writes). A fresh/replaced/test database mints a NEW uuid → no authority row
matches → plain TS behavior for that store, and the module's rows for the old uuid go
inert (visible in status, GC after a retention window). Duplicate-open (two databases,
same project path, different uuids) is therefore structurally impossible to conflate.

R3-B3 DELIVERY ACK + CACHE-SAFE DISMISSAL. (a) New adapter call `transform.ack(pass_id)`
sent by the TS adapter AFTER applyNativeMessagesVerbatim + boundary validation succeed
(i.e. module bytes actually reached the served array); LKG fallback, boundary reject,
and apply failure send `transform.nack(pass_id)` (or nothing — un-acked = not delivered).
Ack means host acceptance, never provider success. Crash between apply and ack =
at-least-once delivery, stated and accepted: the note may surface twice, never zero
times silently. (b) Dismissal rule, cache-safe by doctrine: bytes already anchored in
served output are PRESERVED verbatim (frozen replay, like every other served byte) until
their carrier message leaves the window through normal fold/coverage; dismissal only
prevents NEW surfacing and future re-anchoring. No retraction, no dismissal-driven fold.
The anchor sweep (v3 B5) is re-scoped to match: it prevents REUSE of the anchor for new
deliveries; it does not strip persisted replay state for bytes already served.

R3-H1 STRUCTURAL CONTEXT.DB ENFORCEMENT. Marker enforcement is not per-call convention:
context.db gains its own guard TRIGGERS on memories/notes tables (INSERT/UPDATE/DELETE
→ RAISE(ABORT) when the authority_managed marker row is present for the project and the
write is not privileged). Privileged writers (mirror application, seed, drain, schema
migrations, clearSession) set a per-connection `PRAGMA application_id`-independent flag:
a session-scoped temp table row (`_mc_privileged_writer`) the triggers check — temp
tables are per-connection, so privilege cannot leak across processes. This covers every
writer shape (plugin, Pi, CLI, dashboard db.rs, single .run() calls, future code) at the
database layer. Dashboard: guard triggers make its writes fail closed; the UI adds the
read-only notice for UX, but correctness does not depend on it. Note mutations
(update_note, delete_note, dismiss_note) are covered identically.

R3-H2 U11 SCOPE PIN: PROJECT-OWNED SMART NOTES ONLY. Session notes (session_id-scoped,
no project identity) STAY TS-OWNED in this unit — they are transient, per-session, and
never render into m0/m1. U11 moves project-scoped notes and smart notes (which carry
project identity already). clearSession keeps deleting TS session notes unguarded (they
are TS-owned); the guard triggers scope to project-owned rows via the project column.
A later unit may migrate session notes with a backfill; out of scope here, named.

R3-H3 LITERAL SCHEMA MAP. The build spec ships a column-for-column table: every existing
TS column BY NAME (type, status, content, surface_condition, ready_at, ready_reason,
manifest_json, compiled_check, check_hash, check_cron, check_failure_count,
check_network_failure_count, check_quarantined_until, check_next_due_at,
check_compiled_at, check_false_since_at, check_last_liveness_at, last_checked_at,
check_status, check_version, policy_version, harness, anchor ordinal, dismissed_at,
timestamps) mapped 1:1 to module columns with identical nullability/defaults; genuinely
NEW module columns (source_key columns, anchor_block_id, delivery-ledger linkage)
listed separately; `surfacing`/`surfaced` are MODULE-INTERNAL states — the mirror
projects both back to TS `active` (ready-consumed) so TS/dashboard status enums are
untouched in this unit.

R3-M1 EPOCH TRANSITION TABLE. The bump predicate is an explicit OLD/NEW rule evaluated
in the write transaction: bump iff foreign_visible(OLD) && !foreign_visible(NEW), where
foreign_visible(row) := status='active' AND row.shareable=1 AND row.scope allows
workspace AND category ∈ the workspace's share_categories AND the project is a workspace
member. Grants (visible gained) deliberately do NOT bump (ride the next natural bust).
The one-time fingerprint fold at upgrade (every workspace session folds once when the
epoch component first appears) is priced, called out in release notes, and covered by a
migration golden test.

R3-M2 TRIGGER SNAPSHOT CONTRACT. Feed triggers enumerate columns literally: INSERT/
UPDATE append json_object(...) over NEW (full row), DELETE over OLD; content_hash =
the stored normalized_hash column (not a re-computation); no-op UPDATE writes are
filtered by a WHEN clause comparing NEW vs OLD; every migration that adds a column to a
feed-covered table MUST regenerate the trigger in the same migration (checklist item in
the migration template + a schema test asserting trigger SQL mentions every column).

R3-L1 Dismissal is a STATUS UPDATE on the feed (not a tombstone); the anchor-reuse sweep
keys on the dismissal-status feed row. Tombstones remain reserved for true deletion.

## v5 pins (round-4 REVISE verdict; binding on every build mason)

P1 BARRIER SPANS THE FLIP. The PREPARING `BEGIN IMMEDIATE` on context.db is held
through seed capture, content verification, AND the transition write that flips the
authority row to MODULE; commit releases it. No permit can produce an unseeded row
because no writer can start while the barrier holds and issuance is already stopped.
(If seed duration under the write lock proves operationally hostile on huge pools, the
fallback is the round-4 alternative — transaction-time permit redemption + generation
revocation — but that is a design change requiring re-review, not a mason choice.)

P2 PRIVILEGE VIA CONNECTION-LOCAL UDF, not TEMP table. Persistent guard triggers call
`mc_privileged_writer()`; every managed writable opener (plugin sqlite.ts chokepoint,
dashboard db.rs, CLI database-access) registers it default-false; scoped wrappers
enable it only inside validated seed/mirror/drain/migration/clearSession operations.
A connection that never registered the function fails writes CLOSED (SQLite errors on
the missing function), which is exactly the safe default for unknown future writers.
node:sqlite/bun:sqlite/rusqlite all support scalar UDF registration; the build adds a
cross-backend registration test.

P3 UUID RECONCILIATION AT EVERY WRITABLE OPEN. Writable open of context.db (plugin,
Pi, dashboard, CLI) reads the store uuid + marker state and, when a module is
reachable, reconciles against the authority row BEFORE serving writes; marker-absent +
authority-row-present = REGRESSED = guard triggers install the marker back (repair
under a write barrier) and writes stay closed until repair completes. Engram restore
integration: the restore path itself re-runs this reconciliation before handing the
database to any consumer. Named new work: dashboard/CLI opens currently do none of
this; the "restore then immediate dashboard write" test is mandatory.

P4 IRREVERSIBLE ACCEPTANCE POINT for ack. rust-mode-transform.ts gains an explicit
acceptance boundary: before it, any failure restores raw/LKG and nacks; after it, the
served bytes are final for this pass — ack transmission failure and later bookkeeping
throws are logged and MUST NOT re-enter the rollback path or mutate output.messages.
The broad catch is split accordingly (mechanical refactor, covered by fail-first tests
for a throw on each side of the boundary).

P5 ONE CANONICAL VISIBILITY PREDICATE. `foreign_visible(row, workspace)` is defined
once (module SQL + mirrored TS SQL, kept literally identical in a shared doc-tested
constant): status IN ('active','permanent'), not expired per the existing expiry
policy, shareable=1, scope in the literal allowed set, category ∈ share_categories,
writer project ∈ workspace members, foreign := reader project ≠ writer project. Render,
delta, watermark, FTS, and the epoch-bump OLD/NEW test all use it; a golden test
asserts the module and TS predicate strings stay in sync.

P6 NOTES OWNERSHIP EXACTNESS. Owned set := type='smart' AND project_path IS NOT NULL.
Guard triggers: INSERT judges NEW, DELETE judges OLD, UPDATE judges OLD OR NEW (so
re-pathing a note to NULL cannot escape). The literal column table includes id,
session_id, project_path; dismissed_at is classified NEW (module-side); the table is
golden-tested against PRAGMA table_info(notes) so schema drift breaks the build, and
the real source schema is read from migrations v1+v29+v47 state, not from memory.

P7 NULL-SAFE TRIGGER COMPARISONS. Feed no-op filtering uses `NEW.col IS NOT OLD.col`
throughout; plain != is forbidden (misses NULL transitions); a trigger-SQL lint test
asserts it.

## End-state honesty

After U9-U11 the TS side still owns: scheduling/leases, prompts/parsers/appliers,
smart-note evaluation, mirror cursors, unified search, embeddings, and the RPC/TUI
surface. That is the deliberate trust/capability boundary (network, sandbox, config,
multi-process coordination), not yet the fully stateless adapter of memory #8858.
The remaining distance is named for the record: scheduling move, search/embedding move
(gated on Synapse cutover), and RPC-to-subc management surface — separate future units,
out of scope here.
