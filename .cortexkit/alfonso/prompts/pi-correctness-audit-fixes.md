# Fix batch: Pi correctness audit (5 Critical / 2 High / 1 Medium)

Repo ~/Work/Projects/CortexKit/magic-context, branch subc-migration. A blind adversarial audit of the Pi plugin returned these findings with file:line evidence. For EACH: first verify at source (citations below are from HEAD at audit time and should be close); if a finding is wrong, reject it in your report with evidence instead of "fixing" it. All fixes must preserve the cache law: bytes byte-identical pass-over-pass for unchanged messages; mutations first-apply only on cache-busting passes; failure paths must never ship bytes whose replay state didn't persist.

## C1 — reasoning cleared on the wire without its durable watermark
context-handler.ts:4304-4347 + 4426-4431: an execute pass clears reasoning in workingMessages; if the session_meta watermark write throws, the exception is swallowed and the cleared bytes still ship. Next pass reads the old watermark → restores original reasoning → prefix bytes flip.
FIX: persistence-before-mutation ordering or mutation rollback — if the watermark write fails, this pass must NOT ship the cleared bytes (skip the clearing for this pass: restore/skip the mutation, log, retry next execute pass). Test: fault-inject the meta write (seam or mock) and assert the outgoing messages still carry the original reasoning AND the next pass behaves identically (no byte flip between the two).

## C2 — fallback-tag adoption: sibling insertion between re-probe and allocation still flips tag identity
context-handler.ts:1472-1490 (re-probe + early return), 3853-3872 (allocation), storage-tags.ts:1302-1319 + 1248-1262 (collision folding prefers the fallback survivor → deletes the real-id tag allocated by the racing pass → §N§ flips next pass). The earlier re-probe fix narrowed but did not close the window.
FIX: close the decision under one serialization boundary — run the adoption decision AND the skip decision inside a BEGIN IMMEDIATE transaction (the same lock the adoption body already takes), i.e. move the "is there anything to adopt" check inside the transaction instead of before it; or make collision folding prefer the REAL-id tag (keep N stable, fold the fallback INTO it) — evaluate which is smaller/safer and say why. The invariant to pin in a test: with a sibling connection inserting a fallback row at the worst interleaving point (test seam between probe and allocate), the §N§ assigned to the message NEVER changes across the next pass.

## C3 — stable-id scheme stamped before the cutover pass completes
context-handler.ts:1593-1597 stamps the new scheme during adoption; if the pass later fails (throw before commit, context-handler.ts:2695-2713), the next pass sees scheme=current and skips forced placeholder rediscovery (4570-4573) → old pi-msg-* stripped ids stop matching → previously stripped messages REAPPEAR.
FIX: defer the scheme stamp to after the pass's transcript commit succeeds (same staged pattern as the reuse window: record-intent in memory, persist on success). Test: fail the pass after adoption (fault injection), assert the scheme is NOT stamped and the next pass re-runs cutover with placeholder rediscovery forced.

## C4 — placeholder splice unconditional even when CAS persistence fails (VERIFIED at source)
strip-placeholders-pi.ts:127-183: discovered ids are added to the in-memory set and messages spliced BEFORE persistence; applyStrippedPlaceholderDelta (storage-meta-persisted.ts:1843-1877) can return false after retry exhaustion and the result is ignored → pass T removes the message, pass T+1 restores it.
FIX: persist FIRST (or check the return): only splice ids whose persistence succeeded; on CAS failure, leave the message in place this pass (it re-discovers next busting pass). Watch the prune path too — a failed delta must not leave the in-memory idsToStrip diverged from durable state (rebuild the in-memory set from the CAS-merged result the helper returns, or re-read). Test: make the delta apply fail; assert zero splices this pass and byte-identical output on the following pass.

## C5 — mid-turn release valve unlocked by synthetic user-shaped messages
read-session-pi.ts:188-200 hasRealUserAfter accepts any role:"user" without checking synthetic/custom provenance; boundary-execution.ts:30-42. A synthetic user-shaped entry (e.g. injected steer content that lands as user role) breaks the mid-turn lock and lets execute-class mutations first-apply mid-turn.
FIX: define "real user" from branch-backed entry identity — the entry must exist in the Pi branch as a genuine user message entry (check via the entry-id map / custom-type absence), not merely role==="user" on the wire shape. Mirror the OpenCode semantics (synthetic:true excluded). Test: interrupted assistant + synthetic user → still mid-turn (defer); interrupted assistant + REAL user → released.

## H1 — old-Pi status fallback is model-visible
pi-command-utils.ts:127-149: when registerEntryRenderer is absent/failed, sendCtxStatusMessage falls back to sendMessage — model-visible, can steer mid-stream (this includes async historian failure notices, context-handler.ts:3016-3028).
DECIDED FIX (do not re-litigate): remove the sendMessage fallback entirely. When the renderer API is absent, statuses go through appendEntry anyway (persisted, non-LLM, invisible in old-Pi TUI) and ADDITIONALLY sessionLog. Statuses are nice-to-have; leaking into model context is a correctness bug. Update the PARITY.md paragraph accordingly. Keep the Channel-2 nudge regression test (it must REMAIN sendMessage).

## H2 — Pi has no processed-image strip (wrong shape assumption)
context-handler.ts:4157-4163 + PARITY.md:560-569 claim Pi images are URL-based; actually Pi carries base64 data+mimeType on user and toolResult images (transcript-pi.ts:95-106, 123-130) — processed screenshots ride every later prompt forever.
FIX: implement the processed-image strip for Pi mirroring OpenCode's frozen-id pattern exactly (detect-and-freeze affected ids ONLY on cache-busting passes once the image is old/processed per the OpenCode watermark rule, replay the frozen set on EVERY pass — processed_image_stripped_ids already exists in session_meta and is already clone-copied). Reuse OpenCode's constants/thresholds; replace image parts with the same placeholder text OpenCode uses. Look at the OpenCode implementation (strip-content.ts / stripProcessedImages) and keep semantics parity. Update PARITY.md (delete the wrong paragraph). Tests: frozen-id replay byte-identity across busting→defer passes; images newer than the watermark untouched; clone inherits the frozen set (existing clone test may cover the meta field — extend if not).

## M1 — token-cache plain-object guard is shallow
