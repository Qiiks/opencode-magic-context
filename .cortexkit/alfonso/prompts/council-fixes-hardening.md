Five verified findings from a release council. Read current code first.

## H1: subagent-skip gate on /ctx-wrapup (both harnesses) + Pi caveman explicit subagent gate
Neither wrapup entry checks isSubagent: packages/plugin/src/hooks/magic-context/command-handler.ts (~598-610 executeWrapup branch) and packages/pi-plugin/src/commands/ctx-wrapup.ts (command execute ~146+). A subagent session reaching the command would run the historian and write compartment state conflicting with primary-session invariants (historian/compartments are primary-only). At both entry points, resolve the session meta and refuse with a short message when isSubagent. 
Also: packages/pi-plugin/src/context-handler.ts caveman heuristics path — OpenCode structurally excludes subagents from caveman via the !reducedMode gate (transform.ts ~1761); Pi's caveman gating rides config only. Add an explicit isSubagent short-circuit at Pi's caveman branch (heuristic-cleanup-pi caveman deepening call site in context-handler) so the "subagents never get caveman" invariant is enforced structurally, not architecturally. Tests: wrapup refused for subagent sessions on both harnesses; Pi caveman skipped for isSubagent even when enabled.

## H2: renewal timers must never throw
The 60s wrapup-marker renewal and lease-renewal setInterval callbacks call updateWrapupInProgress / renewCompartmentLease, whose BEGIN IMMEDIATE can throw SQLITE_BUSY under cross-process contention — an uncaught throw from a timer callback. Sites: packages/plugin/src/hooks/magic-context/wrapup-orchestrator.ts (~167-171 lease, ~285-290 marker), packages/pi-plugin/src/commands/ctx-wrapup.ts (~235-239, ~331-333). Wrap each timer body in try/catch: transient errors are a no-op renewal (the 5-min TTL absorbs a missed beat; say so in the comment); ownership-loss (null return) keeps its existing abort semantics — do not let the catch swallow the null-handling. Test: a throwing renewal does not unhandled-reject and the loop continues.

## H3: OpenCode m[0] cache must invalidate on project-identity change
packages/plugin/src/hooks/magic-context/inject-compartments.ts: M0M1State/cached markers do not store the project identity, and mustMaterialize never compares it — a session that materialized under a cold dir: fallback keeps serving that baseline after identity heals to git:. Pi already guards this (inject-compartments-pi.ts ~926-934 returns "project_change"; also see its adoptCachedPiProjectIdentity legacy-null lazy adoption). Mirror on OpenCode: store the resolved projectIdentity in the persisted m0 snapshot markers (storage-meta-shared.ts already supports an identity column per the Pi side — verify), compare in mustMaterialize (a mismatch is a genuine m[0]-content HARD trigger, reason "project_change"), and treat legacy null as unknown → adopt current identity WITHOUT a fold (one-time lazy adoption exactly like Pi). This is cache-critical: adoption must not bust; only a real identity CHANGE may fold. Tests: identity change triggers materialize with reason project_change; legacy-null adopts silently with byte-identical replay; steady-state same-identity passes unaffected (byte-identity test).

## H4: last-known-good git identity should consult ancestors
packages/plugin/src/features/magic-context/memory/project-identity.ts: lastKnownGitIdentityCache is keyed by exact canonical cwd. Transient git failure at /repo/subdir with a prior success only at /repo falls back to dir: and splits the repo. In reuseLastKnownGitIdentity (or its caller), when the exact key misses, walk the canonical path's ancestors (bounded by the hasGitDir walk semantics, include the realpath variant consistent with hasGitDir) and reuse the nearest ancestor's cached git: identity. Only consult the cache — never spawn git on this path. Tests: subdir transient failure reuses the parent repo's cached identity; unrelated sibling dirs do not cross-contaminate.

## H5: re-check wrapup marker after compartment-lease acquisition (TOCTOU)
Trigger-fired historian checks isWrapupInProgress then acquires the compartment lease (packages/plugin/src/hooks/magic-context/compartment-runner.ts ~112-122; Pi packages/pi-plugin/src/context-handler.ts trigger path ~2989-2997 then lease at spawn). A peer process can pass the marker check before wrapup commits its marker, then take the lease afterwards. Cheap close: immediately after acquiring the lease, re-check isWrapupInProgress; if now live, release the lease and skip (same log/latch cleanup as the pre-check skip). Both harnesses. Test: marker appearing between check and lease acquisition (inject via test seam or direct DB write between steps) → run skipped, lease released.
