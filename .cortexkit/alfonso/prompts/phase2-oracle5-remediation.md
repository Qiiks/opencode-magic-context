## H1: no-cooldown fence cleanup is not atomic

`abandon_matching_run_without_cooldown` (crates/mc-module/src/historian.rs ~1427-1450) does store.load() then store.commit() as separate steps. An invalidating transform can commit N -> N+1 between them; the cleanup's CAS loses, the durable historian state stays Publishing, and a LATER recovery path arms the ordinary failure cooldown — exactly the cooldown the FenceRejected path exists to avoid.

Fix: add a store-side atomic operation `McStore::abandon_historian_run_if_matching { session_id, predicate (firing_seq, producer_run_id, chunk_fingerprint), detail }` that inside ONE fenced transaction (with_conn_fenced) re-reads the historian state, checks the predicate match + non-Idle, and commits the Idle transition with failure_backoff_at_ms = NULL, bumping row_version like any commit. It must NOT take an expected_row_version from the caller (the whole point is surviving a concurrent bump); the fenced transaction IS the atomicity. Replace the load+commit pair in abandon_matching_run_without_cooldown with it. Consider whether abandon_matching_run_with_detail has the same race; if yes, route it through the same store op with an Option<i64> backoff parameter and delete the duplicated logic.
Test (deterministic race): use a store hook or the existing connect_failure_commit_hook pattern to commit a cache-state bump between the fence rejection and the cleanup; assert final state is Idle, failure_backoff_at_ms is None, an immediate retry is admitted (producer starts increments), and additive tables unchanged. Fail-first: with the old load+commit pair the cleanup loses CAS and the state stays Publishing.

## H2: restart reattach publishes unfenced

Reattach (historian.rs ~1238-1256) explicitly publishes with publication_fence: None. After a module restart, a transform can replace the raw tail while preserving the historian predicate and revert_epoch; the stale reattached run then publishes compartments/facts derived from pre-restart bytes against the new rows.

Fix: fence reattach publications on the transform-snapshot generation observed AT REATTACH START. Mechanism: when the reattach path assembles (in mc-module/src/lib.rs where reattach constructs its HistorianFiringTask / drives historian::reattach), capture the session's current snapshot-cache state: generation if an entry exists (InFlight OR Ready both carry generations), or an explicit Absent marker. Build a reattach fence (same HistorianPublicationFence trait) that at publication, under the snapshots lock, accepts IFF the session's cache entry state matches the captured observation: same generation still present (InFlight or Ready with generation == captured), or still Absent when Absent was captured. Any new begin() after reattach start changes the generation and must reject with FenceRejected (which now, with H1, cleans up atomically without cooldown). The organic PRESSURE-FIRED path (non-reattach, non-wrapup) stays unfenced: it assembles and publishes within one continuous drive with the live-session guard held, no snapshot dependency; state this in a comment.
Test (deterministic reattach interleave): drive a reattach to the await-output stage, use the hook to begin() a transform (generation change), producer completes, assert publication is rejected, historian state Idle without cooldown, ALL additive tables + publication floor unchanged. A control arm without the interleave publishes normally. Fail-first: with fence None the compartments land.
