## Unit A — CRITICAL: compartment wire shape (council #1)
TS `serializeCompartment` (shadow-sender.ts:584+) emits nested `start`/`end` objects. Rust `ShadowCompartmentWire` (lib.rs:267) requires FLAT `start_message: i64`, `end_message: i64` (ordinals), `start_message_id`/`end_message_id` (bare ids, defaulted). Fix TS to emit the flat shape the parser requires:
- `start_message` = start absolute ordinal, `end_message` = end absolute ordinal (the i64s Rust wants)
- `start_message_id` / `end_message_id` = the FLAT BLOCK IDs (`mid#index` from flatBlockIdForRawMessage) — CHECK against how the Rust store/compose actually uses end_message_id (boundary anchor vocabulary is flat block ids; see transform.rs mint-absent guard comments ~1157-1166). The bare message id goes NOWHERE unless a Rust field consumes it — do not invent fields the parser drops.
- Keep every other field name/type exactly matching ShadowCompartmentWire (sequence i64, title, content, p1-p4 Option<String>, importance i32, episode_type Option, legacy i32, created_at i64).

## Unit C — HIGH: live-path safety (council #3)
transform.ts ~457-462: `cloneForShadow(messages)` + `resolveDeclaredTrimForShadow` run OUTSIDE any try/catch, on the live transform path, BEFORE the transform runs. A throw rejects the user's real pass. Fix:
- Wrap ALL shadow capture work (pre-transform capture AND the post-transform enqueue block) in fail-open try/catch that logs `shadow: capture failed (ignored)` and disables nothing on the live lane.
- Consolidate clones: currently cloneForShadow at capture + cloneJson inside resolveOrdinalsForShadow's annotate + denormalize = up to 3 full-array JSON round-trips per pass. Get it to ONE clone of the input array (capture point) and reuse; annotation may mutate the already-cloned copy freely.
- Move the heavy work (denormalizeShadowOutput, ordinal resolution) INTO the async queue worker (runQueue/processPass) so the hot path only does: one clone + snapshot of cheap scalars + pushWork. CAREFUL: ordinal resolution reads the transform's scoped raw-message cache — moving it async loses the primed cache. That is ACCEPTABLE (the by-id fallback + full read path works; verify with the below-floor test) but verify readRawSessionMessages outside an active cache scope opens its own read and doesn't throw when opencode.db is busy — wrap in the same fail-open.
- Do NOT regress the ordering guarantees: capture must still snapshot input BEFORE the transform mutates messages, and declared-trim-before must be read before the transform runs. Only the EXPENSIVE serialization moves async.

## Unit D — m0-mutation structural changes force reset (council #2 + #4 together)
Design decision (made by Alfonso, implement as specced): the TS sender STOPS sending `m0_mutations` (Rust parser has no such field — it was silently dropped anyway) and instead treats m0-mutation advance as a RESET trigger:
- Keep m0_mutation_id in the TS watermark struct (it already gates state_sync change detection).
- In processPass/buildStateSyncPayload: when current watermarks' m0_mutation_id > lastAcked's, do NOT build an incremental sync — queue a shadow_reset (reason "m0_mutation") followed by a FULL state_sync (force=true re-sends all compartments/memories). This heals recomp/delete/merge (which delete+recreate compartments below the acked watermark — the exact council #4 corruption) because reset wipes the shadow lineage and the full sync re-seeds it.
- Also remove the `watermarks` field from the state_sync wire body OR add it to ShadowStateSyncWire as consumed input — council found Rust drops it silently. Cleanest: keep TS-side watermarks purely local (change detection), send only `acked_watermarks`-relevant content, and let Rust keep computing its ack from content as it does today (lib.rs:2176 fallback). Pick ONE and make the fixture (Unit B) enforce it.
- Test: recomp-style scenario — sync 3 compartments, ack, delete + recreate sequence 2 with different content in the TS db, next pass must produce reset + full resync (assert transport call order), not an incremental sync.

## Unit F — belts (council #5 wedge + #6 socket, both dissented — implement the cheap belts, not redesigns)
- Wedge belt: in processPass, if `state.blockedUntilReset && !state.requireResetReason`, set `requireResetReason = "unknown_block"` so a reset is ALWAYS re-queued (makes Opus's self-heal argument true by construction).
