## Fix 1 (High): zero-block / system endpoints publish an impossible boundary anchor
historian_chunk.rs last_block_id fabricates `<mid>#0` for messages with no flat blocks (~:665-670); system-role messages are passed to the builder with an empty block vector, losing their real last-block identity (~:332-350); a multi-block system message records `#0` not its true last flat block. Validation maps that fabricated id without checking existence (historian_validate.rs:800-840). A structurally-valid split ending a persisted compartment on a zero-block ordinal PUBLISHES, then the mint-absent guard (transform.rs:1089-1191) detects the impossible anchor and can WEDGE materialization until re-cut.
FIX: (a) preserve the REAL last flat-block id for system/excluded content where one exists (a multi-block system message must record its true last flat block id, not #0); (b) mark genuinely zero-block ordinals as UNANCHORABLE (not a fabricated #0); (c) REJECT at validation any compartment whose END ordinal is unanchorable (a compartment must not end on a line that cannot anchor a boundary). This moves the failure from a post-publish wedge to a clean pre-publish validation reject. Tests: a compartment ending on a zero-block ordinal → rejected (not published-then-wedged); a multi-block system message → records its true last block id; a compartment ending on a real block → still publishes.

## Fix 2 (Medium): discard-last sparse-ordinal + side-channel off-by-one
(a) The lookahead sufficiency test subtracts ordinal NUMBERS (chunk.end_index - last_end) instead of counting PRESENT messages (historian_validate.rs:470-477). With sparse ordinals (proxy re-minting), one real lookahead message separated by a large retired-ordinal gap is misclassified as ample lookahead → the unreliable final compartment is wrongly RETAINED (should be discarded + re-read). FIX: count PRESENT ordinals after last_end, not the ordinal arithmetic difference.
(b) Side-channel anchors are documented 1-based (historian_validate.rs:126-143) but keep_side_channel accepts index 0 because it tests only `index <= persisted_count` (~:935-943). So origin_compartment=0 evades discarded-tail fact/observation/primer suppression → double-store risk. FIX: require `1 <= index <= persisted_count`.
Tests: sparse chunk with one real lookahead message across an ordinal gap → discard-last fires (not retained); origin_compartment=0 → rejected/suppressed correctly.

## Fix 3 (Medium): producer envelope hardening
(a) length_capped is detected (historian_producer.rs:795-841,1027-1036) but consulted only AFTER validation already ran (historian.rs:1189-1211); the parser regex-scans usable fragments without requiring a complete <output> root (historian_validate.rs:224-296), so a length-capped response with closed compartments + a valid unprocessed_from can validate and PUBLISH a partial. FIX: reject length_capped output BEFORE parsing; require one complete <output> root document (reject truncated/rootless output).
(b) unit_text accepts nested/flat text from ANY control unit — it never checks the unit type is assistant_message (historian_producer.rs:983-1007) → replay/example-bleed possible if another unit shape carries text. FIX: collect text only from assistant_message units.
Tests: a length-capped-but-closed output → rejected before publish; a rootless/truncated document → rejected; text from a non-assistant unit → not collected.

## Fix 4 (Medium): 64-bit lineage hash
Producer session id uses only 8 hex chars (32 bits) of FNV-1a (historian.rs:694-723). Adversarial session keys could collide → recreates the shared-producer-session condition the design eliminates. FIX: use the full 64-bit hash (16 hex chars). Add a collision/isolation regression + a concurrent reattach-publish test if not already covered.
