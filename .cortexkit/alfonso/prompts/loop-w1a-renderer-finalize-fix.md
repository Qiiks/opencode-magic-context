## Fix 1 (HIGH): compartment titles can forge headings / escape <session-history>
decay-render.ts compartmentHeading() interpolates c.title VERBATIM into `## {start}-{end} · {date} · {title}`. Titles are historian-authored (LLM output). A title containing "\n## 9-9 · fake" forges a second compartment heading; a title "</session-history>" closes the wrapper early; both decay-render's own consumers and dashboard db.rs stop at the first closing tag → truncated token attribution / history extraction. The BODY is guarded (guardCompartmentBody) but the TITLE is not. Rust decay_render.rs compartment_heading has the identical hole.
FIX: canonicalize the title to a single line in BOTH renderers before interpolation — collapse ALL line breaks (\n, \r, \r\n, and Unicode line/para separators U+2028/U+2029) to a single space, and neutralize a leading "## " (the title must never be able to start a heading — e.g. collapse internal "\n## " is moot once newlines are gone, but also guard a title that after newline-collapse contains " ## " mid-string cannot forge because a heading only matters at line-start; the newline collapse is the load-bearing fix). Do NOT XML-escape < > in the title for the heading format (headings aren't XML — but the "</session-history>" escape works because a consumer regex looks for the literal closing tag; verify the consumers: decay-render.ts history-slice logic, m0-token-breakdown.ts, execute-status.ts, dashboard db.rs session-history parser — if ANY of them find the wrapper's closing tag by literal string match, a title containing that literal still breaks them even on one line). So: also neutralize the literal strings "</session-history>", "<session-history>", and a leading "## " sequence within the title — replace the "<"/">" in a title that contains a session-history tag with the fullwidth or escaped form, OR (cleaner) XML-escape < and > in titles in BOTH renderers (the heading is plain text so &lt;/&gt; in a title renders literally and harmlessly, and it kills the closing-tag forge). Pick the cleaner option (escape < > in title) and apply identically TS+Rust. Titles are already escaped nowhere today — confirm no double-escape. This changes rendered bytes ONLY for compartments with special-char titles; on the Rust module bump COMPARTMENT_RENDER_FORMAT_EPOCH cre1→cre2 (compartment_coverage.rs / lib.rs) so the transition is a coordinated HARD. TS lane needs no epoch (renders fresh on next natural HARD; cached m0 replays until then). Add differential fixtures: title with embedded "\n## ", title "</session-history>", title with < > & , title starting "## ", title with U+2028.

## Fix 2 (HIGH): an exception after message mutation ships a partial, unfinalized array
transform-postprocess-phase.ts runs finalizeMessageRepresentation as the LAST step before the normal return (~:1380) but NOT in a finally. Throwable ops run AFTER messages are already mutated (pending ops, heuristics, m0/m1 injection) — e.g. getStrippedPlaceholderIds → storage-meta-persisted.ts throwing SQLite prepare/get (~:1807). On throw, finalization is skipped, the outer wrapper messages-transform.ts catches and RETURNS having already mutated output.messages by reference, while its log/comment claim "Continuing with unmodified messages." No snapshot/rollback exists. Result: OpenCode sends a partially-transformed array without the final representation strips (the double-bust class today's fix was meant to close, via the error path).
FIX (choose the correct one, justify): the real invariant is "on transform failure, send the array EXACTLY as OpenCode gave it to us (unmodified), never a partial mutation." Because postprocess mutates output.messages IN PLACE, the outer wrapper must either (a) snapshot the input message array shape and restore it on catch, or (b) the transform must operate such that a mid-pass throw leaves a consistent (fully-replayed) array. (a) is the robust fix: in messages-transform.ts, before calling the inner transform, capture what's needed to restore (the messages array is the concern — a structural snapshot/clone of output.messages references, or capture length+contents sufficient to revert). On any non-transient catch, restore output.messages to the captured state so the "unmodified" contract is TRUE. Weigh the cost: this is the RARE error path (not the hot path), so a clone on the catch-preparation is acceptable ONLY if it's cheap — prefer capturing a shallow snapshot of the array (Array.from(output.messages)) BEFORE the inner call and swapping contents back on catch (splice-replace), which is O(n) refs, no deep clone. If even that shallow snapshot is deemed too costly per-pass, the alternative is to guarantee finalization runs via try/finally inside runPostTransformPhase so at least the representation is always consistent — but that does NOT fix a throw BEFORE finalization leaving other partial mutations, so (a) at the wrapper is the complete fix. Implement (a). Update the now-true comment. Add a test: inject a throwing getStrippedPlaceholderIds (failpoint/mock) mid-postprocess → assert output.messages is byte-identical to the input the wrapper received (fully unmodified), and the error is logged/surfaced.

## Fix 3 (MEDIUM): TS/Rust legacy-body truncation + line-ending parity
decay-render.ts legacy truncation slices by UTF-16 code units; Rust decay_render.rs by Unicode scalar values (the Rust comment admits BMP-only agreement). A legacy `U:` body with emoji near the 420/1200 boundary renders different bytes, and TS can slice through a surrogate pair. Also: TS body guard `replace(/^## /gm, ...)` treats a lone `\r` as a line start (JS multiline), Rust only replaces `\n## `.
FIX: define ONE shared truncation semantics and match both. Unicode-scalar (chars) is the correct unit — make TS slice by code points (spread to array or Intl.Segmenter/[...str] then slice+join) to match Rust, OR make Rust match TS's UTF-16 units — pick scalar (cleaner, no surrogate splits) and align TS to it. Match the line-ending guard: both must treat \r, \n, \r\n identically (normalize or guard all). Extend the golden generator (crates/mc-core/testdata/gen-golden.ts) with emoji-near-boundary legacy bodies, lone CR, CRLF, and a U+2028 case; regenerate the golden from TS and confirm Rust matches byte-exact.
