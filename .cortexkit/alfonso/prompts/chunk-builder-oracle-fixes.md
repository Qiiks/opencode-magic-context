## Finding 1 (input shape — the real design fix): zero-block messages vanish
`build_historian_chunk(live: &[FlatBlock], ...)` derives messages via `grouped_messages(live)` (historian_chunk.rs:293-358). A CK message whose content flattens to ZERO blocks is absent from `live`, so it is never seen — not even as noise meta. Its ordinal then appears in no ChunkLine, and `validate_chunk_coverage` (historian_validate.rs:561-587) requires contiguous lines → the fold/publish fails on a legitimate conversation. In TS, EVERY RawMessage exists; no-text messages go to pendingNoiseMeta and are absorbed into the next block's meta.

FIX (decided, do not improvise an alternative): change the builder input to iterate the AUTHORITATIVE message list. Signature becomes `build_historian_chunk(messages: &[CkIngressMessage], blocks: &[FlatBlock], start_ordinal, token_budget, eligible_end_ordinal)` (or an equivalent struct): group `blocks` by mid once, then iterate `messages` in order — ordinal/role/mid come from the message, blocks attach by mid lookup, and a message with no blocks takes the SAME path as a TS no-text message (pendingNoiseMeta). The assembler already runs where both the ingress array and the projection exist (transform.rs handle path) — thread accordingly. `total_count`/`has_more` also derive from `messages` (absolute count), not from block ordinals.

## Finding 2: duplicate tool-call ids resolve to the wrong summary
`build_tool_call_summary_lookup` keys a HashMap by bare call_id with or_insert first-wins (historian_chunk.rs:607-639). CK permits reused call ids; `project_messages` proves it and pairs results to calls by FIFO arc (ck_wire.rs:345-369): a ToolResult FlatBlock's `arc_id` IS the flat block id of its PAIRED ToolCall. FIX: key the lookup by the CALL's flat block id (`<mid>#<index>`), and resolve a result via ITS OWN `arc_id` — exact pairing, no ambiguity. Keep the bare `TC: {tool_name}` fallback when arc_id is None/missing from the map.

## Finding 3: truncateHistorianInputIfNeeded is not the TS port

The current Rust approximation (historian_chunk.rs:525-534) drops the marker and cuts differently.
